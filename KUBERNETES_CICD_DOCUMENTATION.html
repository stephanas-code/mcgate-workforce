1 System Architecture Overview

McGate Workforce is an enterprise workforce management, payroll, biometric attendance, project execution, and analytics platform. It is deployed into namespace mcgate on the same production Kubernetes cluster (k8s-cp-01) that hosts MyClan and StorePro.

2 Storage & Pod Rollout Design (The Recreate Strategy)

Single-Replica & ReadWriteOnce (RWO) Storage Design Rule: The web application and database workloads mount persistent volume claims backed by storageClassName: local-path using ReadWriteOnce access mode. Under the standard Kubernetes RollingUpdate strategy with maxSurge: 1, Kubernetes boots the new replica before terminating the old one, which causes persistent volume detachment deadlocks because the node storage lock remains held by the original pod. Setting strategy: { type: Recreate } guarantees that the old pod cleanly stops and unmounts the volume before the new pod mounts it and starts up.

5 Native Health & Readiness Probes

To ensure Kubernetes does not route traffic before the app is ready and to prevent restart loops, dedicated lightweight JSON endpoints are configured directly in Django core:

  • /health/ — Liveness Probe: Returns HTTP 200 JSON {"status": "healthy"} confirming the Gunicorn worker thread is alive.
  • /ready/ — Readiness Probe: Runs connection.ensure_connection() to confirm database connectivity before the pod accepts client requests.

6 Operational Runbook & Quick Commands

Standard operator commands when interacting with the cluster:

# Apply or update all manifests
kubectl apply -f k8s/workforce.yaml

# Check rollout status
kubectl rollout status deployment/mcgate-workforce-web -n mcgate --timeout=300s

# View running pods and IPs
kubectl get pods -n mcgate -l 'app in (mcgate-workforce-web,mcgate-workforce-postgres)' -o wide

# View live application logs
kubectl logs -f deployment/mcgate-workforce-web -n mcgate --tail=100

# Emergency Rollback to previous working version
kubectl rollout undo deployment/mcgate-workforce-web -n mcgate
